유닛 테스트에서는 각 함수의 정상 케이스와 예외 케이스를 고루 다루고, 통합 테스트에서는 컴포넌트 간의 상호작용을 검증하는 등 각 테스트가 검증하고자 하는 것과 그 방법에 대해서 잘 이해하시게 된것 같네요. 잘하셨습니다.

Q) 
테스트는 그 순서를 바꿔 실행해도 성공해야 한다. 이걸 어떻게 확인할 수 있을까요? 적당히 몇 개 섞어서 실행해볼 수는 있을 것 같은데, 모든 순서 조합을 다 변경해볼 수는 없을 것 같아서요. 이것을 보장, 확인할 수 있는 테스트 방법론이 있을까요?

=> 도형님이 생각하신 것처럼 적당히 몇 개 섞어서 해 보고자 하는 요구사항을 반영하여 테스트의 순서를 정해진 순서대로 하는게 아니라 섞어서 실행시킬 수 있는 옵션이 있습니다. jest의 --randomize 옵션이다 vitest의 -sequence.shuffle 등의 옵션을 통해서 실행 순서를 랜덤하게 처리해볼 수 있습니다.


Q) 테스트 코드를 잘못 작성했는데, 조건이 어떻게 잘 맞아서 우연히 통과할 수도 있겠구나 싶었습니다. 이런 상황을 방지하려면, 테스트를 최대한 구체적으로 작성해서 그럴 상황이 없게끔 하는 것 말고는 방법이 없을까요?

=> 맞습니다. 테스트를 했는데 우연히 통과하는 것을 false positive라 따로 키워드가 있을만큼 중요한 개념이죠. 조금씩 상황을 늘려가며 충분한 테스트 케이스를 모아가는 전략으로 다양한 케이스를 확보하는게 필요하겠죠. 

=> 테스트를 전문으로 작성을 하는게 업무가 아니라면 테스트 코드는 결국 메인 업무를 위한 작업이다보니 완벽한 테스트들이 아니더라도 메인 업무를 도와가는식으로 충분히 쌓아갈 수 있습니다.
